# 商家小程序（员工端）

店员在门店用的小程序：查会员余额、开单（填会员权益金额、请顾客签合同，签完自动充值）、充值、扫会员码消费、看本店流水；店长和超级管理员还能冲正。只记账，不收款，不接任何支付。

**消费必须先用手机扫顾客的会员码**（顾客在会员小程序首页点「会员码」），扫到才能填金额，不能直接输入扣款。

**开单的会员权益金额在顾客签完合同后才充值到账**，没签、撤销、拒签、过期都不充值。

微信原生 + TypeScript。接口说明见 [docs/backend/m1-auth-stores.md](../../docs/backend/m1-auth-stores.md)、[docs/backend/m2-ledger.md](../../docs/backend/m2-ledger.md)、[docs/backend/pay-code.md](../../docs/backend/pay-code.md) 和 [docs/backend/m4-esign-sandbox.md](../../docs/backend/m4-esign-sandbox.md)（开单、签完充值）。

## 页面

| 页面 | 路径 | 做什么 |
| --- | --- | --- |
| 店员登录 | `pages/login/login` | 微信手机号一键登录。只有已开通、在职的店员能进 |
| 工作台（底部第一栏） | `pages/index/index` | 当前门店；最上面「扫码消费」；输入手机号查会员，查不到时「为这个手机号开单」；「开单」入口；最近办理过的 5 位会员 |
| 会员 | `pages/member/member` | 全公司通用的总余额；「充值」「扫码消费」（扫到的必须是这位会员的码）；「办理权益单」；待签署的权益单可「接着签」；在你的门店办理过的最近 10 笔（超级管理员看全部门店） |
| 记账 | `pages/entry/entry` | 充值或消费：填金额（元）实时显示记账后余额，二次确认后提交。消费页显示「已扫码 · 几点前有效」，没带码时只有「扫会员码」按钮；码过期、用过时弹窗「重新扫码」，金额不用重填 |
| 开单 | `pages/order/order` | 四步：① 输顾客手机号（新顾客可填称呼）② 填权益：第一项「会员权益金额」，下面是权益方案的内容，选合同模板 ③ 生成合同，屏幕上出签署二维码请顾客用微信扫码签，每 4 秒自动查一次 ④ 签完自动充值到账，弹出会员小程序码请顾客扫码登录。新顾客在生成合同时开卡；店长和超级管理员可以撤销没签的合同 |
| 本店流水（底部第二栏） | `pages/ledger/ledger` | 当前门店的流水，按天分组，可选今天 / 近 7 天 / 近 30 天和类型 |
| 流水详情 | `pages/ledger-detail/ledger-detail` | 一笔的全部信息；超级管理员或这家店的店长可以冲正，店员看到「请联系店长」 |
| 我的（底部第三栏） | `pages/mine/mine` | 姓名、当前门店、角色、退出登录 |
| 切换门店 | `pages/stores/stores` | 一人在多家店有角色时切换。停用的门店不能选 |

## 记账为什么不会记重、记错

- 金额在程序里一律是整数分，只在输入和显示时换成元（`utils/money.ts`），最多两位小数，单笔 1 分到 100 万元。
- 每次点「确认」生成一个请求号。网络断了、没收到结果时，页面锁住金额，只能「重试」，重试带同一个请求号，服务端只记一笔。
- 消费前先按当前余额拦一次「余额不足」；最终以服务端为准（别人刚扣过时会提示没记上并刷新余额）。
- 冲正每笔只能一次，原因必填；服务端再按权限和「只冲一次」校验。
- 消费带着扫到的会员码提交。码是一次性的，扫码后 5 分钟内由扫码的人在这家店用；服务端在扣款的同一个事务里把码用掉。
- 开单的会员权益金额写进合同，合同发出后就改不了（数据库也拦着）。顾客签完后服务端按权益单记一笔充值，请求号由权益单决定，不管刷新、回调、会员端查询来几次都只记一笔。

## 本地开发

1. 起本机接口：`pnpm dev:api`。演示假手机号登录时在 `apps/api/.env` 里设 `WECHAT_PHONE_MOCK=true`（正式环境无效）。
2. 微信开发者工具导入 `apps/staff-mp`，AppID 填测试号（`project.config.json` 里的 `touristappid` 只是占位，Secret 不进仓库）。
3. 接口地址在 `config.ts`，默认 `http://localhost:3000`。开发者工具里勾选「不校验合法域名」。
4. 测试号拿不到手机号时，可以在开发者工具的 Storage 里加 `dev.mockPhone`（例如种子超管 `13800000000`）用假手机号登录；`dev.apiBase` 可以临时换接口地址。这两个只在开发版生效，界面上没有入口。

node tools/mp-preview/shoot.mjs apps/staff-mp/preview/scenario.mjs --out /tmp/staff-shots

场景脚本会往**本机**数据库写演示门店（滨江店、西湖店）、员工（陈店长、李晓）、会员、权益方案、合同模板、权益单和流水，建议用一个空的本地库。开单那几张会让假电子签平台把合同标成「顾客已签」，再截签完弹码和到账。消费都按真机顺序准备：会员出示会员码、店员扫码、带码扣款。截图里「扫到」的码是场景脚本现拿的会员码（`scanResult`）。预览是近似效果，真机以微信开发者工具为准。

## 本机试开单（不连电子签）

本机没有电子签沙箱时，用假电子签平台模拟顾客签字：

1. 按上面「截图」的前两行起假电子签平台和接口。
2. 商家后台「合同模板」里新建模板，电子签模板 ID 填 `member-benefit-demo`，绑上一个权益方案，启用。
3. 员工小程序「开单」走到签合同那一步后，电脑浏览器打开 <http://127.0.0.1:3902>，在待签署的单子后面点「模拟顾客签完」。
4. 回到小程序，几秒内自动显示「已充值到账」并弹出会员小程序码。本机没配会员小程序时显示的是演示码，扫了打不开。

会员小程序码由接口 `GET /member-app/code` 现取（微信 `getwxacodeunlimit`，缓存 12 小时）。正式上线前在 `apps/api/.env` 里配好 `WECHAT_MEMBER_APPID`、`WECHAT_MEMBER_SECRET`；会员小程序还没发正式版时，`WECHAT_MEMBER_CODE_ENV` 可以改成 `trial`（体验版）。
