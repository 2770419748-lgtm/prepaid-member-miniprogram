# 储值会员小程序 · UI/UX 设计规范 v1.1

> **状态：** v1.1（主色已定；可用门店与后台登录观感已补）  
> **日期：** 2026-10-28（Asia/Shanghai）  
> **对齐：** 技术方案定稿；三端第一版一起做  
> **维护：** 产品设计；观感验收结论发项目群  
> **交接：** 2026-10-28 起项目交 Claude 继续；本规范以仓库 `docs/design/ui-design.md` 为准

## 1. 范围与原则

三端：会员微信小程序 + 商家 Vue3 网页后台 + 商家端小程序。

- **清晰优先：** 余额、权益、门店、签署状态一眼可读，不堆营销干扰。
- **信任感：** 储值与签署页留白充足、文案克制、关键数字层级最高。
- **微信习惯：** 导航、列表、表单跟小程序常见模式。
- **两端一致：** 会员端与商家端共用色板、字号阶梯与间距刻度。

**不做：** 小程序内微信支付充值/在线支付扣款（线下记账，线上展示与签署）。

**会员端禁止：** 任何查看员工、店长、店员列表或详情的入口与文案。

## 2. 信息架构

| 端 | 模块 | 用户要完成的事 |
| --- | --- | --- |
| 会员端 | 首页/会员卡 | 看余额、权益摘要、快捷入口 |
| 会员端 | 权益 | 读清权益细则与适用规则 |
| 会员端 | 明细 | 按时间看消费/储值流水 |
| 会员端 | 可用门店 | 看可用门店、地址、电话；一键导航与拨号 |
| 会员端 | 权益单签署 | 阅读并线上确认会员权益单 |
| 商家后台 | 登录 | 手机号 + 密码；首次强制改密 |
| 商家后台 | 开卡/登记 | 登记会员并开卡 |
| 商家后台 | 充值/扣款 | 门店记账，写流水 |
| 商家后台 | 门店与店员 | 管门店、角色与账号 |
| 商家后台 | 权益单 | 模板配置、发起签署、查状态 |
| 商家小程序 | 店员高频 | 开卡/记账/查余额（可裁报表） |

**必须：**

- 未签权益单：进首页先引导签署，完成后再进主流程。
- 余额为空态：0 元也展示卡片结构，不放假数据。
- 会员只能读门店公开信息，不能碰员工相关能力。

### 3.2 字号与层级

| 用途 | 字号 | 字重 | 说明 |
| --- | --- | --- | --- |
| 余额大数字 | 36–40 | Semibold | 首页卡片唯一焦点 |
| 页面标题 | 18–20 | Semibold | 导航栏或页头 |
| 卡片标题 | 16 | Medium | 模块名、列表主文 |
| 正文 | 14 | Regular | 说明、表单标签 |
| 辅助 | 12 | Regular | 时间、次要提示 |

### 3.3 间距与圆角

- 间距刻度：4 / 8 / 12 / 16 / 24 / 32。页面左右边距 16，卡片内边距 16，卡片间距 12。
- 圆角：卡片 12，按钮 8，标签/胶囊 999。
- 阴影：仅会员卡或关键余额卡可用极轻阴影；列表行不用阴影，靠分割线。

## 4. 关键页面要点

1. **会员首页/卡面：** 顶区会员身份 + 余额大数字 +「元」；中区权益摘要 ≤3 条；底区明细/门店/签署入口；主按钮不超过一个。权益卡片下放置入口文案「可用门店 · N家」。
2. **使用明细：** 按日分组；每行类型、金额（加减色区分）、门店、时间；需空态。
3. **可用门店（坤总 2026-10-28 定稿）：**
   - 一店一张卡片：店名 → 详细地址 → 营业时间 → 距离（仅会员同意定位后显示；近的排前；无定位不伪造距离）。
   - 卡片右侧两个操作：「导航」为信任蓝 `#1677FF` 主按钮，先在地图展示门店位置，再跳转本机导航（高德/腾讯/百度）；「电话」直接拨号。
   - 微信侧优先用打开地图能力，会员可再选导航 App。
   - 空态：一行灰字「暂无可用门店，请联系商家」，不留空白页。
   - 不出现员工、角色、内部账号任何信息。
4. **权益与签署：** 权益页只读；签署页全文可滚、底部固定同意区；签完成功态回首页。沙箱期 UI 可标「测试签署」。
5. **商家网页后台：** Vue3 + Ant Design Vue；桌面优先；危险操作二次确认；按角色藏菜单。
6. **商家后台登录（2026-10-28 定稿）：** 手机号 + 密码（非短信）。主按钮整行宽、信任蓝 `#1677FF`。需有：输错锁定提示（连错 5 次锁 15 分钟）、首次登录强制改初始密码流程。去掉调试壳按钮与「占位」文案。
7. **商家后台概览：** 多卡并排时等高；左上角带品牌标识；数据接通后用数字卡（会员数、储值总额、今日消费），并补空状态。
8. **商家端小程序：** 对齐后台高频路径更短；与会员端共用色板与字号阶梯。

## 5. 交互与反馈

1. 加载：列表骨架或中性 loading，不用整页闪白。
2. 成功：Toast 短文案；储值/签署可加结果条。
3. 失败：说清原因与下一步，不弹技术错误码给会员。
4. 金额：统一两位小数；扣减危险色「-」，增加成功色「+」。
5. 脱敏：手机号中间四位掩码。
6. 登录失败：白话提示剩余次数或锁定剩余时间，不暴露技术细节。

## 6. 验收观感清单

- [ ] 余额数字是页面视觉焦点，字号明显高于周围
- [ ] 主色克制：主按钮与关键状态，不大面积铺色
- [ ] 卡片间距、边距符合 8 的倍数
- [ ] 未签署、零余额、无门店、无明细均有明确空态
- [ ] 签署流程文案可读、按钮区不挡正文
- [ ] 商家表格对齐、状态标签色区分且不花哨
- [ ] 三端色板、圆角、字号阶梯一致
- [ ] 会员端无任何员工入口；可用门店含地址、导航、电话
- [ ] 后台登录主按钮为 `#1677FF` 整行宽；无「占位」调试文案
