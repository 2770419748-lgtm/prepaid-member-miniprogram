## M2 已完成

- 开卡：店员登记手机号，同一事务建会员和余额为 0 的钱包。会员先在小程序登录过也能补开。一个手机号只能开一张卡。
- 充值、扣款：只记账。余额全公司通用，任何门店都能扣。余额不足拒绝。
- 并发：钱包用 `version` 乐观锁，冲突自动重读重试。测试里 5 笔同时透支只成功 1 笔，11 笔同时加减账一分不差。
- 冲正：补记一笔反方向的 `REVERSAL` 整笔抵掉原流水，原流水保留并标记已冲正。
- 防重复提交：前端带 `requestId`，网络重试或连点只记一笔。
- 流水只追加：没有修改、删除接口；数据库触发器也拒绝修改、删除和清空。余额不能为负、前后余额对不上的流水，数据库都拒绝写入。
- 会员端：`GET /members/me/wallet` 看余额，`GET /ledger` 看自己的明细，不含操作店员和备注。
- 迁移：`20261027200000_m2_wallet_ledger`。新增会员称呼、开卡时间、冲正关联、请求号，以及 CHECK 约束和只追加触发器。

## M1 已完成

- 小程序登录仍是微信手机号（会员、员工各一套测试号）。网页后台员工登录改为手机号 + 密码，不做短信验证码。
- 密码只存 bcrypt 哈希。同一账号连续错 5 次锁定 15 分钟。新建或重置后 `mustChangePassword` 为真，第一次登录必须改初始密码。
- 超级管理员可重置密码。店长不能重置。
- 技术部指出的两处越权已收紧：店长不能把店员提为店长，不能修改自己或其他店长的角色。店长只能管理普通店员。
- 门店有详细地址、经纬度（`lat` / `lng`）、联系电话、营业时间（`businessHours`，文本）。超级管理员和本店店长可维护。店长不能改营业状态。
- 会员只读接口 `GET /members/stores` 返回在营门店的名称、地址、坐标、电话、营业时间，供导航和拨号。没有员工字段。会员不能访问员工接口。
- 关键写操作写审计记录（含改密码、重置密码），记录里没有密码明文。没有审计查询接口。
- 迁移：`20261027180000_store_contact_and_staff_password`。没有新增数据表，原有十一类实体仍在。

接口说明见 [backend/m1-auth-stores.md](./backend/m1-auth-stores.md)。

## 已知限制

- `mustChangePassword` 只在登录和 `GET /auth/me` 里返回。服务端没有因此拦住其他接口，网页后台要根据这个标志强制进入改密码页。小程序登录不走密码。
- 密码长度 8 到 64 位，并限制在 bcrypt 的 72 字节以内。没有更复杂的强度规则。
- 锁定按员工账号计算，不按 IP。锁定中即使密码正确也会拒绝。未知手机号与密码错误用同一句「手机号或密码错误」。
- 会员门店列表是该公司全部在营门店，不按距离筛选。停用门店不返回。经纬度要成对填写。
- 假手机号开关 `WECHAT_PHONE_MOCK` 默认关闭。`NODE_ENV=production` 时强制关闭。开发环境打开时，启动日志会警告。
- 本地种子账号 `13800000000` 的初始密码是 `Init12345`，只用于本机演示，第一次网页登录必须修改。
- 说明页 `GET /docs` 和跨域保持现状，部署时再收。没有接真实短信，也没有微信支付。正式签署保持关闭。
- 本里程碑没有改 `apps/admin-web`、小程序和 `docs/frontend`。网页后台和小程序仍要各自接这些接口。

## 接手要点

1. 先看本文件和开着的 PR。后端在 `apps/api`，文档在 `docs/backend/`。设计以 [docs/design/ui-design.md](./design/ui-design.md)（v1.1）和 [docs/design/DESIGN-HANDOFF.md](./design/DESIGN-HANDOFF.md) 为准。
2. 不要部署、不要打开 `ESIGN_PRODUCTION_ENABLED`，不要引入微信支付。
3. 和仓库文档或现有 Prisma 模型冲突时，以仓库文档和现有 schema 为准。不要拆掉已有的十一类实体。
4. 公开文案继续用「储值会员」，不要写具体商户或产品名。
5. 网页后台是手机号 + 密码。不要改回短信验证码，除非坤总另有书面要求。
6. 店长权限不要放宽：只能给普通店员分配店员角色，不能改店长和自己的角色。
7. 余额只能经 `WalletService` 改动。不要绕开它直接写 `wallets` 或 `ledger_entries`。
