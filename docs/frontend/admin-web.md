# 商家网页后台（apps/admin-web）

> **状态：** 第一版已实现。Vue 3 + Vite + Ant Design Vue + Pinia。  
> **日期：** 2026-10-27（Asia/Shanghai）  
> **硬约束：** 不接微信支付，充值只记账；电子签只走沙箱，页面标「测试签署」；公开文案只用「储值会员」；主色 `#1677FF`。

## 1. 页面

| 菜单 | 路由 | 谁能看 | 做什么 |
| --- | --- | --- | --- |
| 登录 | `/login` | 所有人 | 手机号 + 密码。输错提示「连续输错 5 次锁定 15 分钟」，锁定时说明多久后再试 |
| 修改密码 | `/change-password` | 已登录 | 第一次登录或密码被重置后强制进入。改完回登录页用新密码重新登录（服务端已让旧登录作废）。接口返回 `MUST_CHANGE_PASSWORD` 时也会跳到这里 |
| 概览 | `/dashboard` | 所有员工 | 会员数、储值总额（仅超级管理员）、今日充值、今日消费（扣除冲正后），最近流水，快捷开卡 / 充值 |
| 会员 · 开卡 | `/members/open` | 所有员工 | 手机号、称呼、开卡门店，二次确认。已开过卡时给出「查看这位会员」 |
| 会员 · 会员查询 | `/members`、`/members/:id` | 所有员工 | 完整手机号查任一门店的会员；手机号片段或称呼只查本店会员。详情页显示总余额（视觉焦点）、本店范围内的流水、充值 / 发起权益单 |
| 记账 · 充值记账 | `/billing/recharge` | 所有员工 | 找会员 → 填金额（元）和备注 → 确认弹窗（记账后余额、提醒「只记账不收钱」）→ 结果 |
| 记账 · 流水查询 | `/ledger` | 所有员工 | 按会员手机号、门店、类型、日期筛选；详情抽屉；超级管理员和原门店店长可冲正 |
| 门店与员工 · 门店管理 | `/stores` | 所有员工（只读） | 超级管理员新建、编辑、停用 / 恢复；店长编辑本店资料 |
| 门店与员工 · 员工管理 | `/staff` | 店长及以上 | 开通账号（随机初始密码）、改名、门店角色、停用；超级管理员另可改手机号、重置密码 |
| 权益单 · 发起与签署 | `/benefits/sign-flows` | 所有员工 | 选会员 + 已启用模板 + 门店发起，弹出签署二维码；刷新状态、下载签好的 PDF、撤销（超级管理员或本店店长） |
| 权益单 · 模板配置 | `/benefits/templates` | 超级管理员 | 权益方案（条目、规则、草稿 / 启用 / 下架）；绑定 e签宝沙箱模板编号 |
| 对账与记录 · 当日对账 | `/reconciliation` | 所有员工（按门店范围） | 某天各门店充值、消费、冲正，净额和合计；超级管理员另有全公司余额日结和「余额核对」 |
| 对账与记录 · 操作记录 | `/audit-logs` | 所有员工（按范围） | 开卡、记账、冲正、门店和员工变动、改密码等，内容翻成白话 |

菜单按角色隐藏，配置在 `src/menu.ts`；路由 `meta.minRole` 再拦一次，后端仍是最终权限判断。

**后台不做消费扣款。** 消费必须由店员在员工小程序里扫顾客的会员码后再填金额（坤总 2026-10-27 要求），后台菜单和按钮里没有扣款入口，旧链接 `/billing/consume` 只显示这句提示。

## 2. 约定

- **金额：** 接口一律整数分。输入按字符串换成分（`src/utils/money.ts`），不经过浮点；显示两位小数和千分位，加为成功色 `+`、减为危险色 `-`。单笔上限 100 万元，与后端一致。
- **防重复记账：** 每次打开确认弹窗生成一个 `requestId`，网络重试或连点都带同一个号。断网时提示「再点一次确认不会重复记账」。冲正、发起签署同理。
- **当前门店：** 顶栏选择，记在本机浏览器。开卡、记账、发起签署默认用它；停用的门店不能选来记账。
- **手机号：** 列表里中间四位打码；会员详情和记账确认里显示完整号码，方便核对。
- **错误：** 后端的中文业务错误（余额不足、已开卡、无权操作该门店等）原样显示；英文字段校验、服务器故障换成白话（`src/api/http.ts`）。登录过期回登录页。
- **冲正：** 页面上解释为「记错了账，补记一笔反方向的抵掉」。按钮只对超级管理员和原门店店长显示，冲正流水和已冲正的不显示。
- **电子签：** 目前只有沙箱，签署相关页面都标「测试签署」。接口见 [backend/m4-esign-sandbox.md](../backend/m4-esign-sandbox.md) 第 4.1–4.3 节；表单长度限制与后端一致。

## 3. 本地运行

```bash
pnpm --filter api prisma:migrate
pnpm --filter api prisma:seed
pnpm --filter api start:dev
pnpm --filter admin-web dev
```

打开 <http://localhost:5173>，用种子账号 `13800000000` / `Init12345` 登录，第一次会要求改密码。接口地址来自 `apps/admin-web/.env.development` 的 `VITE_API_BASE`。

检查：

```bash
pnpm --filter admin-web typecheck
pnpm --filter admin-web test     # vitest：金额换算、角色与菜单、错误文案、操作记录白话
pnpm --filter admin-web build
```

截图：按 [apps/admin-web/preview/README.md](../../apps/admin-web/preview/README.md) 起本机接口和假电子签平台，造演示数据后自动走一遍 35 个场景。

## 4. 已知限制

- 后端登录失败不返回剩余次数，页面只能统一提示「连续输错 5 次锁定 15 分钟」。
- 没有做报表导出、短信、会员资料修改和停用（后端暂无接口）。
- 宽度按桌面设计（≥1280px），窄屏可用但未专门适配。
- 全量引入 Ant Design Vue，组件库单独打包约 1.4 MB（gzip 约 440 KB），内部后台可以接受。
