# 扫码消费（会员码）— 后端说明

> **状态：** 已实现（`apps/api` 的 `PayCodeModule`，扣款在 `WalletService`）。  
> **日期：** 2026-10-27（Asia/Shanghai）  
> **来由：** 坤总 2026-10-27：「消费的逻辑我现在看到是店员直接输入做扣减 把这个更改成 店员扫码顾客的会员二维码 然后才能输入对应的抵扣金额」；「店员扫码是用手机进行扫描顾客的会员二维码」。  
> **硬约束：** 不接微信支付，只记账。余额只经 `WalletService` 改动。

---

## 1. 流程

```
会员小程序「会员码」 POST /members/me/pay-code        → 18 位数字，画成二维码，每 30 秒换一张
员工小程序「扫码消费」 wx.scanCode → POST /pay-codes/scan → 认出是哪位会员，码锁给这位店员和这家门店
店员填金额            POST /wallets/:memberId/consume（带 payCode）→ 扣款和「码已用」在同一个事务里
会员小程序每 2 秒查一次 GET /members/me/pay-code/:id   → 显示「门店已扫码」，扣完显示金额、门店、剩余余额
```

充值、开卡、查会员、冲正都不变，不需要会员码。商家网页后台没有扣款入口（见 `docs/frontend/admin-web.md`）。

## 2. 规则

1. **码的样子：** 18 位数字，`8` 开头，最后一位是 Luhn 校验位，摄像头扫错一位会被认出来。库里只存 SHA-256，不存明文。
2. **有效期：** 出示后 60 秒内要扫；会员页每 30 秒自动换码。会员换了新码，之前没扫的码马上作废。
3. **一次性：** 扣款成功后码标记为已用，再扫或再拿来扣款都会被拒。截图里的码要么过期、要么已用，不能拿来消费。
4. **扫码锁定：** 扫到后码锁给扫码的店员和门店 5 分钟。别的店员、别的门店再扫会被拒；同一人在同一家店重复扫没关系。
5. **扣款时再核一次：** 码必须是这位会员的、由本人在本店扫的、还在 5 分钟内、还没用过。任一条不满足都不扣款。
6. **扣款失败不浪费码：** 余额不足、金额填错被拒时，码还保持「已扫」，店员改金额再提交即可。
7. **防重复提交照旧：** 同一个 `requestId` 重试，即使码已经被这一笔用掉，也返回第一次的结果（`replayed: true`），不会提示「码已用过」。
8. **会员页防截图：** 出示时屏幕常亮、调到最亮；截屏和录屏时隐藏画面（`wx.setVisualEffectOnCapture`）；检测到截屏马上换码。这些是体验上的防护，真正的保证是第 2、3 条。

## 3. 接口

| 方法 | 路径 | 谁能用 | 请求 | 返回 |
| --- | --- | --- | --- | --- |
| POST | `/members/me/pay-code` | 会员 | — | `{ id, code, expiresAt, refreshAfterSeconds }`。没开卡或卡已停用 400 |
| GET | `/members/me/pay-code/:id` | 会员 | — | `{ id, status, expiresAt, storeName, entry }`。`status`：`ACTIVE` 等着扫、`SCANNED` 门店已扫、`USED` 已扣款（`entry` 是那一笔，会员视角）、`EXPIRED` 过期。不是自己的码 404 |
| POST | `/pay-codes/scan` | 店员及以上 | `code`（扫到的原文）, `storeId` | `{ member, expiresAt }`：会员卡（同 `GET /members/:id`）和扫码锁定的到期时间 |
| POST | `/wallets/:memberId/consume` | 店员及以上 | `storeId`, `amountCent`, `payCode`, `remark?`, `requestId?` | 同 M2。`payCode` 必填 |

扫码和扣款的报错都是白话，员工小程序直接显示：

| 情况 | 状态码 | 提示 |
| --- | --- | --- |
| 扫到的不是会员码（网址、别的二维码） | 400 | 这不是会员码，请扫顾客小程序里的会员码 |
| 码过期、已换新码、别的公司的码 | 400 | 会员码已过期 / 已失效，请顾客刷新会员码后重新扫 |
| 码已经扣过款 | 409 | 这张会员码已经用过了，请顾客刷新会员码后重新扫 |
| 被别的店员或别的门店扫过 | 409 | 这张会员码已经被扫过了，请顾客刷新会员码后重新扫 |
| 扣款没带码 | 400 | 请先扫顾客的会员码 |
| 码不是这位会员的 | 400 | 这张会员码不是这位会员的，请重新扫码 |
| 扣款的人或门店和扫码的不一致 | 403 | 这张会员码不是你在这家门店扫的，请重新扫码 |
| 扫码超过 5 分钟才提交 | 400 | 扫码已超过 5 分钟，请顾客刷新会员码后重新扫 |

## 4. 数据库

迁移 `20261027230000_member_pay_codes` 新建 `member_pay_codes`：

- 状态 `ISSUED`（已出示）→ `SCANNED`（已扫，记扫码人、门店、锁定到期）→ `USED`（已扣款，记用掉的时间和那一笔流水）。
- 状态变化都用带条件的更新（`UPDATE … WHERE status = …`），两台手机同时扫或同时扣款只有一个成功。
- `ledger_entry_id` 唯一：一笔流水只能对应一张码。
- CHECK 约束保证字段和状态对得上；触发器拒绝修改或删除 `USED` 的记录，用过的码永久留底。
- 因为码引用了流水，`TRUNCATE ledger_entries` 现在先被外键拦下（原来是被只追加触发器拦下），两种都是拒绝。
