# 上线前安全加固

2026-10-28。来源：坤总转来的施工单（服务端强制首次改密、请求号必填、正式环境关文档、收紧跨域、拒绝示例密钥）。逐条对照代码核实后全部成立，按下面的规则实现。

## 1. 服务端强制首次改密

**规则：** 员工用初始密码（新建时设的，或超级管理员重置的）登录网页后台后，在改掉密码之前，服务端只放行两个接口：

| 接口 | 用途 |
| --- | --- |
| `GET /auth/me` | 看自己是谁、是否要改密 |
| `POST /auth/staff/password/change` | 改密码 |

其他接口一律返回 **403**，响应体带固定代码：

```json
{ "statusCode": 403, "code": "MUST_CHANGE_PASSWORD", "message": "请先修改初始密码", "path": "...", "timestamp": "..." }
```

网页后台看到这个代码就跳改密页。没有「退出登录」接口：登录凭证是无状态的，退出就是网页清掉凭证，不需要放行。

**实现：** 全局守卫的一步（`PrincipalGuard`，挂在 `AccessGuard` 里，`APP_GUARD` 全局注册），不是逐个接口判断。放行名单只靠 `@AllowPendingPassword()`，新接口默认被拦。`test/password-change-guard.spec.ts` 会扫描全部 controller 核对名单只有上面两个，以后有人加装饰器测试会失败。

**只拦密码登录：** 登录凭证里记着登录方式（`loginMethod`：`PASSWORD` / `WECHAT`）。员工小程序用微信手机号登录，不输密码、也没有改密页面；如果按「账号还没改初始密码」一律拦，新员工在小程序里什么都做不了。所以只拦 `PASSWORD` 登录的凭证。会员（微信手机号登录）完全不受影响。

**改密、重置后旧登录作废：** `staff.session_version`（迁移 `20261028000000_staff_session_version`）写进登录凭证（`sessionVersion`）。每次请求和数据库比对，对不上就 401「登录已失效，请重新登录」。

- 员工自己改密码：版本号加一，这位员工之前的所有登录（网页和员工小程序）都要重新登录。
- 超级管理员重置密码：`mustChangePassword` 置回真，版本号加一，同上。
- 升级前签发的员工凭证没有版本号，一律当作失效，重新登录即可（还没部署过，不影响谁）。

`mustChangePassword` 每次请求按数据库判断，不写进凭证，所以重置后即使有人拿着新密码登录，也一样被拦。

## 2. 充值、扣款、冲正的请求号必填

`POST /wallets/:memberId/recharge`、`POST /wallets/:memberId/consume`、`POST /ledger/:id/reversal` 的 `requestId` 改为必填（8 到 64 位字母、数字、`-`、`_`，UUID 即可）。不带返回 400「缺少防重复提交的请求号 requestId」。

同一个号提交几次都只记一笔，返回第一次的结果并带 `replayed: true`；同一个号换了金额、门店或会员返回 409。员工小程序、商家后台原本就每次确认生成一个号，不用改；预览和验收脚本已补上。

顺手修的边角：两次带同一个号**同时**冲正一笔充值，原来第二次可能报「余额不足，无法冲正这笔充值」（第一次已经把钱扣回去了）。现在记账事务失败时先查同一个号有没有记过，有就返回那一笔。

## 3. 正式环境不开放接口文档

`NODE_ENV=production` 时不挂 `/docs` 和 `/docs-json`（404）。开发和测试环境照旧。实现在 `src/http-exposure.ts`。

## 4. 正式环境收紧跨域

新配置 `CORS_ORIGINS`：允许跨域调用接口的网页来源，逗号分隔，只写协议和域名，例如 `https://admin.example.com`。

| 环境 | 没配 | 配了名单 | 写了 `*` |
| --- | --- | --- | --- |
| 正式 | 不允许任何网页跨域调（启动日志警告） | 只回应名单里的来源 | **拒绝启动** |
| 开发 / 测试 | 任何来源都放行（本机 vite 调试） | 只回应名单里的来源 | 任何来源都放行 |

格式不对（带路径、没写协议）也拒绝启动。小程序的请求不受跨域限制，不用配。商家后台和接口部署在同一个域名下时可以不配。

## 5. 正式环境拒绝示例 JWT 密钥

`NODE_ENV=production` 启动时检查 `JWT_SECRET`，不合格直接不启动，日志打印原因（不打印密钥本身），退出码 1：

- 空的；
- 等于仓库里出现过的示例、测试或 CI 值（`change-me-in-local-only`、`test-only-jwt-secret`、`ci-only-jwt-secret`、`test-secret`），或含 `change-me`；
- 少于 32 位。

生成方法：`openssl rand -base64 48`。开发和测试环境只要求不为空。实现在 `src/auth/jwt-secret.ts`，登录凭证的签发和校验两处共用。
