# 退余额与会员资料维护 — 后端说明

> **状态：** 已实现。  
> **日期：** 2026-11-04（Asia/Shanghai）  
> **来由：** 上线清单第二优先的两件（[上线清单](https://claude.ai/artifact/4an3CTM1yuZvYHbLTSB5xM) B、C）。坤总 2026-11-04 回「开工」。

## 1. 退余额

顾客要退没用完的储值时用（消保法实施条例第 22 条要求可退）。之前只能整笔冲正，顾客用掉一部分后剩下的退不了。

**规则（Claude 定的默认，可改）：**

1. 只有**超级管理员（任一门店）或这家门店的店长**能办；店员看到「只有超级管理员或本店店长可以退余额」。
2. 新的流水类型 `REFUND`，减余额。**只记账，钱在门店线下退**（现金、转账等）。
3. 可以只退一部分，不能超过当前余额。全部退就填当前余额。单笔上限同充值（100 万元）。
4. **原因和退款方式必填**，写在流水备注里，也写进操作记录（`WALLET_REFUND`「退余额」）。会员端不显示。
5. 停用的会员也能退（先停用、再退余额是常见做法）；门店要在营。
6. 不用扫会员码：退款只有店长、超管能做，而且常有顾客不在场（电话申请、转账）的情况。
7. 退错了可以冲正，钱加回余额（冲正规则不变：超管或原门店店长、一笔只冲一次）。
8. 防重复提交和充值一样，`requestId` 必填。

**接口：** `POST /wallets/:memberId/refund`，请求 `storeId`、`amountCent`、`remark`（必填）、`requestId`（必填），返回和充值一样的 `{ entry, balanceCent, replayed }`。余额不够 400「退款金额超过了会员余额」。

**对账：** 当日对账和概览多了 `refundCount`、`refundCent`、`reversedRefundCent`、`netRefundCent`。冲正按被冲原流水的类型拆成冲回充值、退回消费、冲回退款。
`netChangeCent = netRechargeCent − netConsumeCent − netRefundCent`。余额核对把 `REFUND` 当减、冲回 `REFUND` 当加。

**数据库：** 迁移 `20261104100000_ledger_refund_type`（枚举加 `REFUND`）和 `20261104100100_ledger_refund_check`（前后余额约束加上 `REFUND` 必须是减、不带原流水）。

**流水视图：** 店员视角和会员视角都多了 `reversalOfType`（冲正抵掉的是哪一类），前端据此写「冲正 · 抵掉退余额」「退款撤销」。会员端把 `REFUND` 叫「退款」。

## 2. 会员资料维护

之前没有任何修改会员的入口。登录改成 30 天后，顾客丢了手机，旧手机上的登录一直有效。

**规则（只有超级管理员）：**

| 操作 | 接口 | 要求 | 效果 |
| --- | --- | --- | --- |
| 改称呼 | `PATCH /members/:id` `{ name }` | — | 只改称呼，登录不受影响 |
| 换手机号 | `PATCH /members/:id` `{ phone, reason }` | 原因必填；新号不能是另一位会员的；有没签完的权益单（草稿、待签署）时不能换 | 会员小程序之前的登录全部作废，微信绑定清掉，顾客用新号重新登录后还是同一张卡、同样的余额和流水 |
| 停用 | `POST /members/:id/disable` `{ reason }` | 原因必填 | 登录全部作废，不能登录、充值、消费、开权益单；余额保留，可以退余额 |
| 恢复 | `POST /members/:id/enable` `{ reason }` | 原因必填 | 能重新登录。停用前的旧登录不会复活 |

- 新手机号如果只是顾客用新号登录过一次会员小程序留下的空记录（没开卡、没有流水、权益单和会员码），换号时把这条空记录删掉、让出号码，操作记录里记下 `releasedMemberId`。别的情况一律 409「这个手机号已经是另一位会员的了」。
- 有没签完的权益单时不能换号：e签宝那边的签署人还是旧号，签不下去。先撤销或等签完。
- 操作记录：`MEMBER_UPDATE`「修改会员资料」（`previousPhone`/`phone`、`previousName`/`name`、`reason`）、`MEMBER_DISABLE`「停用会员」、`MEMBER_ENABLE`「恢复会员」。手机号在查询结果里新旧都打码。

**登录作废的做法：** 会员表加 `session_version`（迁移 `20261104100200_member_session_version`），会员登录凭证带 `sessionVersion` 和 `loginMethod: WECHAT`，和员工一样每次请求对一遍，对不上 401。换手机号、停用时加一。没带版本号的旧会员凭证一律 401，要重新登录一次（只影响升级前登录的会员）。
