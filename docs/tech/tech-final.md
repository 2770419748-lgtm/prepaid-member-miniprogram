## 1. 背景与目标

坤总计划于 **2026 年 12 月入职**后将本系统交给公司使用，当前为 **入职前准备**。目标是落地一套「线下充值/消费记账 + 线上会员权益展示与权益单签署」的多门店储值会员体系。

**产品形态（第一版 / MVP：三端一起做，不做二期拆分）**

| 端 | 职责（第一版） |
| --- | --- |
| 会员端微信小程序 | 登录、权益展示、余额与明细、使用门店、线上签权益单 |
| 商家网页后台 | 开卡登记、门店充值记账、消费扣款、查明细、管门店/店员、配置权益单并发起签署 |
| 商家端小程序 | 店员侧便捷开卡/记账/查余额（与后台高频能力对齐，可裁剪报表类低频功能） |
| 后端服务 | 账号、门店、会员账户、流水、权益单与电子签对接、权限 |

**非目标（第一版明确不做）**

- 小程序内微信支付充值 / 在线支付扣款  
- 充值与消费仅在线下门店完成，小程序只做记账与展示

## 6. 核心模块与数据模型要点

### 6.1 模块

1. **组织与权限**：公司 → 门店 → 店员角色（超管 / 店长 / 店员）  
2. **会员**：微信 openid/unionid、授权手机号、会员卡状态  
3. **账户与流水**：全公司通用余额；充值记账、消费扣款、冲正（若启用）；流水不可物理删  
4. **门店**：门店档案、营业状态、可服务范围展示  
5. **权益与权益单**：权益配置、模板绑定、发起签署、签署状态回写、合同文件归档  
6. **审计**：店员关键操作日志（开卡、充值、扣款、发起签署）  
7. **配置开关**：`esign.production.enabled`（正式签署总开关；沙箱联调不受此限）  

### 6.2 关键实体（要点，非最终表结构）

- `org` / `store` / `staff` / `staff_store_role`  
- `member`（手机号、微信标识、开卡门店、状态）  
- `wallet`（member_id、balance、version 乐观锁）  
- `ledger_entry`（类型：充值/消费/冲正；门店；操作员；金额；前后余额；备注）  
- `benefit_plan` / `contract_template`（e签宝模板 ID 映射）  
- `sign_flow`（第三方 flowId、状态、签署链接、本地 PDF 引用、sandbox/prod 标记）  

**账务原则**：任何余额变更必须写流水；扣款前校验余额；用事务 + 乐观锁防超卖。

## 7. 电子签落地路径（e签宝）

### 7.1 选型结论（已定）

- **落地：e签宝**  
  - 开放平台公开 API 标准版约 **8 元/份**（以官网/商务为准），成本随量线性，适合首年份数暂不好估、先按份采购  
  - 有官方「微信小程序内嵌 H5 签署」文档与 demo  
  - 支持企业/个人签与实名；个体工商户可做企业认证  
  - 代价：刷脸需跳「公证签」小程序，接入比腾讯半屏跳转略重  
- **升级选项（一笔带过）**：主体与预算就绪后，若强诉求「微信半屏/整页跳转官方签」体验，可评估迁至 **腾讯电子签**（深度 API 通常需更高版本套餐）。第一版不并行对接。

### 7.2 签署业务规则（已定）

- 签署方：**会员个人签 + 商家企业章**  
- 发起方：商家后台配置权益单模板后，选择会员发起  
- 会员端：权益单列表 → 打开签署页 → 完成后回跳展示「已签署」  
- 归档：签署完成 PDF 落对象存储，并与 `sign_flow` 关联  

### 7.3 接入步骤

1. e签宝开放平台创建应用（**先走沙箱**）  
2. 配置小程序业务域名；按文档内嵌签署 H5；刷脸场景实现中间页跳转公证签小程序  
3. 商家后台：模板配置、发起签署、回调/轮询同步状态、PDF 归档  
4. 会员小程序：签署入口与结果页  
5. **企业章与正式环境**：等 12 月公司主体办理并完成 e签宝企业认证后，配置正式密钥，打开正式签署开关  

### 7.4 沙箱 / 正式开关策略（硬约束）

| 阶段 | 主体 / AppID | 电子签 | 说明 |
| --- | --- | --- | --- |
| 入职前（当前） | 无正式主体；微信 **测试号** | **仅沙箱联调**；`esign.production.enabled = false` | 可端到端跑通模板、发起、回调、归档；不可对外承诺正式法律效力签署 |
| 入职后（约 12 月） | 公司办理主体；正式 AppID | 企业认证 + 企业章；开关打开后正式按份计费签署 | 切换密钥与回调地址；存量沙箱数据不进生产 |

费用：首年份数暂不好估 → **按量预估、先按份采购**，避免年框压预算。
