## 1. 目标与范围

### 目标

交付会员端微信小程序（里程碑 **M3：会员端展示**），会员可查看权益、余额、使用明细、使用门店，并完成线上签署权益单（入口跳转 e签宝）。

- **估时**：约 **10 人天**（对齐定稿「会员小程序 8–12 人天」，取中值并拆分子项，见 §8）
- **路径**：同仓 monorepo → `apps/member-mp`
- **当前仓状态**：空仓，待 **M0** 初始化骨架合入后再落业务页；本说明可先写，**实现等 M0 合入 + M2 账务就绪**

### 范围内（做）— 页面清单

| # | 页面 | 说明 |
|---|------|------|
| 1 | 登录 / 授权手机号 | 微信授权手机号登录（入职前用**测试号**；正式 AppID 12 月后切） |
| 2 | 权益展示 | 当前会员权益包 / 权益项列表与状态 |
| 3 | 余额 | 储值余额展示（全公司通用余额，见定稿） |
| 4 | 使用明细 | 消费 / 充值等流水列表与详情（分页） |
| 5 | 使用门店列表 | 可用门店列表（名称、地址等；详情字段待后端） |
| 6 | 权益单列表 + 签署入口 / 结果页 | 待签/已签列表 → 打开签署 → 回跳结果 |

### 不做清单（明确排除）

- [ ] **小程序内微信支付 / 充值收银台**（硬约束：无小程序内微信支付；充值与消费仅线下门店完成，小程序只做记账与展示）
- [ ] 店员管理、开卡/记账/扣款操作（属商家后台 / 商家小程序）
- [ ] **商家端小程序**（全栈 **M5**，边界知晓即可，本任务不做）
- [ ] 自行实现电子签章 SDK 内嵌（只用 e签宝 H5 / 刷脸中间页）
- [ ] 账务核心逻辑、冲正引擎（属 M2 / 后端）
- [ ] 自行 merge / 部署（须经开发部 → 总经理 → 坤总确认后再执行）

## 4. 页面 / 路由清单与关键交互

> 路径名为建议名；最终以仓内 `app.json` 为准（待 M0）。

| 建议路由 | 页面 | 关键交互 | 依赖 |
|----------|------|----------|------|
| `/pages/login/index` | 登录 / 授权手机号 | 授权手机号 → 换会话 | **待 M1** |
| `/pages/index/index` | 首页 / 会员概览 | 余额摘要、权益入口、待签提醒 | **待 M2** 概览/余额 |
| `/pages/benefits/index` | 权益展示 | 列表、状态标签、空态 | **待 M2 / 权益配置** |
| `/pages/balance/index` | 余额 | 当前余额 | `GET /wallets/:memberId`（M2） |
| `/pages/ledger/index` | 使用明细列表 | 分页；类型筛选若后端支持 | `GET /members/:id/ledger`（M2） |
| `/pages/ledger/detail` | 流水详情 | 金额、时间、门店、备注 | 同上 / 详情字段待后端 |
| `/pages/stores/index` | 使用门店列表 | 列表；导航/电话按需 | `GET /stores`（M2） |
| `/pages/sign/list` | 权益单列表 | 待签 / 已签；入口进签署 | **待 M4** `sign_flow` |
| `/pages/sign/entry` | 签署入口 | 拉签署链接 → 开 web-view | **待 M4** |
| `/pages/sign/result` | 签署结果回跳 | 成功/失败/取消；轮询状态 | `GET /sign-flows/:id`（M4） |

### 4.1 e签宝签署流程（逐步 · 硬约束）

```
1. 商家后台发起签署后，会员端拉取 sign_flow，得到签署链接
2. 小程序用 web-view 打开 e签宝 H5 签署页
3. 刷脸：按 e签宝文档走中间页，再跳转「公证签」小程序
   （需配置业务域名与跳转白名单；正式主体就绪前用测试号能力范围内联调）
4. 完成后回跳小程序结果页
5. 签署状态以服务端回调为准；前端可轮询 GET /sign-flows/:id
6. 正式签署开关关（esign.production.enabled = false）时：
   - 仅沙箱联调
   - UI 可标「测试签署」
   - 不可对外承诺正式法律效力
```

**禁止**：小程序内微信支付；自建刷脸/签章 UI 替代 e签宝中间页。

## 5. 与 M2 相关的只读接口（展示用）

会员端主要消费只读能力（路径可微调，与后端对齐后写 README）：

| 方法 | 路径 | 用途 |
|------|------|------|
| GET | `/wallets/:memberId` | 余额 |
| GET | `/members/:id/ledger` | 明细分页 |
| GET | `/stores` | 门店列表 |
| GET | `/sign-flows/:id` | 签署状态轮询（**M4**） |

请求头：Bearer。错误码（后端约定，前端统一映射）：会员不存在、无权限等；余额不足等主要出现在商家记账侧。

金额单位：与后端 Prisma 字段一致后写进 README，**禁止混用**。

开卡 / 充值 / 扣款接口属商家后台，本端**不调用**写账接口。

## 9. 实现阶段拆分 / 建议 PR 切片（约 10 人天）

按顺序分模块实现（每步建议独立 PR；**PR 链接交开发部 → 总经理 → 坤总确认后再 merge**；可用云端写码改仓）：

1. **仓约定对齐**（0.5 人天）  
   读 README / 定稿 / M0；确认 `apps/member-mp` 为微信原生+TS（或 Taro）；仓仍空或 M0 未合入则停止并反馈。

2. **工程骨架与请求层**（1 人天）  
   页面路由骨架、封装 request（baseURL、Bearer、401、错误码）、环境配置。接口 path 先 typed stub + TODO，对齐 M2/M4 后再填。

3. **登录 / 授权手机号**（1 人天）  
   测试号下授权手机号 + 会话存储；字段严格跟 M1 文档。

4. **首页 + 余额**（1 人天）  
   对接 `GET /wallets/:memberId`；金额按约定单位展示。

5. **权益展示**（1.5 人天）  
   列表、状态、空态（权益配置接口待后端，缺口标 TODO）。

6. **使用明细列表 + 详情**（1.5 人天）  
   `GET /members/:id/ledger` 分页；筛选若后端支持再开。

7. **使用门店列表**（1 人天）  
   `GET /stores`；地图/电话按需。

8. **权益单列表 + 签署入口 + 回跳结果**（1.5 人天）  
   拉 `sign_flow` → web-view H5 → 刷脸中间页约定 → result + 轮询；沙箱标「测试签署」；**无支付**。

9. **联调、体验版、打磨**（1 人天）  
   与 M2 展示联调、与 M4 签署联调；错误态与文案；提测清单；开 PR 交开发部转确认。

**合计约 10 人天**（定稿区间 8–12）。
