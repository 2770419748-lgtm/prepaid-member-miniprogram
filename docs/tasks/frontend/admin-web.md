## 4. 页面 / 路由清单与关键交互

> 路径为建议；最终以仓内路由表为准（待 M0）。

| 建议路由 | 页面 | 关键交互 | 依赖接口 |
|----------|------|----------|----------|
| `/login` | 登录 | 手机号+密码或微信（M1 定） | **待 M1** |
| `/dashboard` | 概览 | 可选摘要；可极简 | 可选 |
| `/members` | 会员列表 | 搜索、状态筛选 | **待 M2** 列表 API |
| `/members/:id` | 会员详情 | 余额、流水入口、发起签署入口 | `GET /wallets/:memberId` 等 |
| `/members/open-card` | 开卡 / 登记 | 表单提交、成功回执 | `POST /members` |
| `/billing/recharge` | 门店充值记账 | 选会员、金额、门店、备注；二次确认 | `POST /wallets/:memberId/recharge` |
| `/billing/consume` | 门店消费扣款 | 选会员、金额、门店、备注；二次确认 | `POST /wallets/:memberId/consume` |
| `/billing/ledger` | 余额与明细 | 筛选、分页、详情抽屉 | `GET /wallets/:memberId`、`GET /members/:id/ledger` |
| `/stores` | 门店管理 | 列表 / 维护（权限内） | `GET /stores` + **待 M1** 写接口 |
| `/stores/:id/staff` 或 `/staff` | 店员账号 | 增删改、角色、归属门店 | **待 M1** |
| `/benefits/templates` | 权益单模板配置 | 列表、编辑、启停、关联 e签宝模板 ID | **待 M4** |
| `/benefits/orders` | 发起签署 / 记录 | 选会员+模板发起；状态刷新 | **待 M4** |
| `/audit`（可选） | 审计对账只读 | 有接口则挂只读表；无则不做 | **待后端** |

### 4.1 关键流程：开卡 →（可选）发起权益单

```
店员/管理员登录（Bearer）
  → 开卡表单 → POST /members
  → 成功后可跳转「发起权益单」
  → 选择权益单模板 → 发起签署（待 M4）
  → 会员在小程序侧走 e签宝 H5 / 刷脸
  → 后台刷新签署状态（回调为准，可轮询）
```

### 4.2 关键流程：充值记账 / 消费扣款

```
选会员 + 当前门店上下文
  → 输入金额与备注
  → 二次确认弹窗
  → POST /wallets/:memberId/recharge 或 /consume
  → 请求头建议带 Idempotency-Key（防重复提交）
  → 成功展示新余额并刷新流水；失败展示后端错误
     （余额不足、会员不存在、无权限、幂等键冲突等）
```

**注意**：后台**不**调起小程序微信支付；线下收款方式文案若需要展示，待业务确认。

## 5. M2 账务接口约定（路径可微调；与后端对齐后写 README）

| 方法 | 路径 | 用途 | Body / 说明 |
|------|------|------|-------------|
| POST | `/members` | 开卡 / 登记 | 字段 **待 M2**（至少含手机号、开卡门店等） |
| POST | `/wallets/:memberId/recharge` | 充值记账 | `{ amount, storeId, remark }` |
| POST | `/wallets/:memberId/consume` | 消费扣款 | `{ amount, storeId, remark }` |
| GET | `/wallets/:memberId` | 余额 | — |
| GET | `/members/:id/ledger` | 明细分页 | query 分页参数 **待后端** |
| GET | `/stores` | 门店列表 | — |

### 5.1 金额单位（硬约定）

- 定稿 / M0 模型使用 **整数分（cent）** 倾向；若最终改为「元」的 decimal 字符串，须与 Prisma 字段 **一次定死**
- 前后端写进 README，**禁止混用**分与元
- 前端展示层负责分↔元显示换算，提交按约定单位

### 5.2 幂等与错误码

- 写操作建议请求头 **`Idempotency-Key`**（防重复点击导致重复记账）
- 前端需映射的错误（文案友好）：
  - 余额不足
  - 会员不存在
  - 无权限
  - 幂等键冲突

字段级 schema **勿编造**；以 M2 OpenAPI / 后端文档为准，到位前用 typed stub + TODO。
